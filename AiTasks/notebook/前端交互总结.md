## 二、项目目录结构

```
project/                        ← 项目根目录
  .index.json                   ← 项目元数据
  .deliverables/                ← 交付物目录（右侧面板管理，左侧不可见）
  .worktrees/                   ← git worktree 存放（不可见）
    task-{slug}/
  .git/                         ← git 仓库（不可见）
  {slug}/                       ← notebook 目录（每个 notebook 一个）
    {slug}.notebook.json        ←   notebook 文件
    .working/                   ←   任务工作文件
  readme.md                     ← 普通文件（自由创建）
```

**dotfile 可见性规则** (服务端 `isVisibleEntry`):
- 非点开头文件/目录 → 可见
- `.index.json` → 可见（白名单精确匹配）
- `*.notebook.json` → 可见（后缀匹配）
- 其他点文件（`.git/`, `.deliverables/`, `.worktrees/`, `.working/`）→ 隐藏

## 三、模块交互流程

### 3.1 认证模块

| 操作 | 组件 | 流程 |
|------|------|------|
| 检查认证 | App | mount → `checkAuthStatus()` → GET `/api/auth/status` |
| 登录 | LoginPage | 输入 token → `login()` → POST `/api/auth/login` |
| 登出 | Toolbar > LogoutButton | `logout()` → 清 token + 关 WebSocket |
| Token 验证 | authSlice | `checkAuthStatus()` 内对已存 token 调 `/api/auth/verify` |

### 3.2 项目管理（ProjectSidebar — L1）

| 操作 | 触发 | 流程 |
|------|------|------|
| 加载项目列表 | mount | `fetchProjects()` → GET `/api/projects` |
| 新建项目 | "New Project" 表单 | `createProject(title)` → POST `/api/projects` → 刷新列表 |
| 进入项目 | 点击项目卡 | `setActiveProject(id, path)` → `sidebarLevel='L2'` |
| 返回项目列表 | L2 返回按钮 | `goBackToProjectList()` → `sidebarLevel='L1'` |

### 3.3 项目文件（ProjectSidebar — L2 上半区）

仅在 `sidebarLevel='L2'` 时显示。**显示项目根目录**（无 `initialPath` 限制）。

| 操作 | 触发 | 流程 |
|------|------|------|
| 浏览目录 | 面包屑 + 文件夹点击 | FileSection 内部 `setSubPath()` |
| 打开 Notebook | 点击 `.notebook.json` | POST `/api/notebooks/open-by-path` → `openNotebookTab()` + `subscribeToSession()` |
| 打开文件预览 | 点击其他文件 | `setOpenFile({path, source:'workspace', sessionId})` → 中心区 FileViewer |
| 新建 Notebook | "+ New Notebook" 按钮 | `createNotebook(projectId, title)` → POST `/api/projects/{id}/notebooks` |
| 上传文件 | 按钮 / 拖入 | FormData POST + progress |
| 新建文件/夹 | 按钮 → 输入名 | POST `/files/new-file` 或 `/files/mkdir` |
| 删除 | 二次确认 | DELETE `/files?path=...` |
| 下载 | 单文件 / 全部 | GET `/files/download` 或 `/files/zip` |
| 拖出到 prompt | 非 notebook 文件 | 拖拽 `[file: path]` 到 textarea |
| 自动刷新 | 定时器 | 10s 轮询（page visible） |

- `baseUrl` = `/api/projects/${activeProjectId}`
- `noDragFilter`: `(name) => name.endsWith('.notebook.json')` — notebook 文件不可拖拽

### 3.3a Library（ProjectSidebar — 下半区，始终可见）

Library 是全局知识库，**不受 L1/L2 切换影响，始终显示**。与上半区之间有可拖拽分隔条。

| 操作 | 触发 | 流程 |
|------|------|------|
| 浏览目录 | 面包屑 + 文件夹点击 | FileSection 内部 `setSubPath()` |
| 打开文件预览 | 点击文件 | `setOpenFile({path, source:'library', sessionId})` → 中心区 FileViewer |
| 上传/新建/删除/下载 | 各按钮 | 标准 FileSection CRUD，`baseUrl` = `/api/library` |
| 拖出到 prompt | 任意文件 | 拖拽 `[file: path]` 到 textarea（需 `workspaceDir` 计算相对路径） |
| 自动刷新 | 定时器 | 10s 轮询（page visible） |
| 调整分隔比例 | 拖拽分隔条 | `setLeftSidebarSplitRatio(0.2~0.8)` |

> L1 项目列表页：上半区显示 ProjectList，下半区显示 Library → 用户在选择项目时也能浏览/拖拽知识库文件。
> L2 项目详情页：上半区显示项目文件 FileSection，下半区显示 Library → 同一界面同时操作项目文件和知识库。

### 3.4 Notebook 标签管理

| 操作 | 组件 | 流程 |
|------|------|------|
| 切换标签 | NotebookTabs | `setActiveNotebookTab(id)` + `setOpenFile(null)` → 切换 notebook/sessionId |
| 关闭标签 | Tab × 按钮 | `closeNotebookTab(id)` → 自动切下一个或清空 |
| Git 标签 | NotebookTabs | `openGitTab()` + `setOpenFile(null)` → `gitTabOpen=true` → 显示 GitHistoryPanel |
| 关闭 Git | Git × 按钮 | `closeGitTab()` → 恢复 notebook 视图 |
| 文件标签 | NotebookTabs | openFile 存在时显示文件名标签（自动激活） |
| 关闭文件标签 | 文件标签 × | `setOpenFile(null)` → 返回 notebook/git 视图 |

> **注意**: 切换 notebook tab 时自动清除 `openFile`（notebookSlice `setActiveNotebookTab` 内置），避免 FileViewer 持有旧 sessionId。

### 3.5 Notebook 主体

| 操作 | 组件 | 流程 |
|------|------|------|
| 发送 prompt | NotebookInputBar | 输入文字 → Ctrl+Enter 或 ▶ → `submitPrompt(source)` → 创建 cell + `executeCell()` |
| 附件上传 | NotebookInputBar + 按钮 | POST `/api/notebooks/{sessionId}/files` → `[file: name]` 引用插入 |
| 拖入文件引用 | textarea onDrop | 拖入 `[file: path]` 文本 |
| 批注转发 | window 事件 | `nb:appendPrompt` CustomEvent → 追加到 textarea |
| Save | NotebookStatusBar | `saveNotebook()` → WS `save_notebook` |
| Export | NotebookStatusBar | GET `/api/notebooks/{sessionId}/export-zip` → 下载 |
| Slice 视图切换 | NotebookStatusBar | `setActiveTab('slice')` ↔ `setActiveTab('notebook')` |

### 3.6 Cell 输出

| 输出类型 | 组件 | 显示方式 |
|----------|------|---------|
| Thinking | ThinkingPanel | 可折叠，默认收起；运行中由 StreamingThinking 替代 |
| Tool Use | ToolsPanel > ToolRow | 可折叠，显示 name/input/result，✓✗ 状态 |
| Text | StreamingText (运行中) / TextOutputView | `<pre>` 文本 |
| Error | ErrorOutputView | 红色 ✕ + 消息 |
| Chart | ChartOutputView | SVG 内嵌（已消毒）|
| Git Diff | GitDiffView | Cell 底部，toggle 展开 |

### 3.7 Slice 视图

| 操作 | 组件 | 流程 |
|------|------|------|
| 生成 Slice | SliceView | `generateSlice()` → WS → 服务端返回 `slice_update` |
| 编辑标题 | SliceSectionCard | 点击标题 → inline input → `updateSliceSections()` |
| 编辑内容 | SliceSectionCard | 点击内容 → textarea → Done 按钮 |
| 排序 | SliceSectionCard | ▲▼ 按钮 → 重排 `order` |
| 删除 | SliceSectionCard | ✕ 按钮 → filter + reindex |

### 3.8 Git History

| 操作 | 组件 | 流程 |
|------|------|------|
| 查看提交 | GitHistoryPanel | `fetchGitLog()` → commit 列表 + SVG lane graph |
| 切换分支 | branch select | `setSelectedBranch()` / `setAllBranches()` → 重新加载 |
| 搜索文件 | search input | debounce 300ms → `setSearch()` → filter |
| 查看 diff | CommitItem > file | 点击展开 → `fetchGitDiff()` → DiffView |
| 复制 hash | commit hash 标签 | `navigator.clipboard.writeText()` |
| 自动刷新 | 定时器 | 3s 轮询，检测新 commit |
| 无限滚动 | scroll handler | 滚到底 → `loadPage(page+1)` |
| localStorage 缓存 | GitCache | 首页默认分支结果缓存，启动即显 |

### 3.9 右侧面板（RightPanel — Deliverables）

| 操作 | 组件 | 流程 |
|------|------|------|
| 展开/收起 | 按钮 ‹/› | `toggleRightPanel()` |
| Deliverables | FileSection | baseUrl = `/api/projects/{activeProjectId}`，`initialPath=".deliverables"` |
| 点击文件 | onFileClick | `setOpenFile({path, source:'deliverables', sessionId})` → 中心区 FileViewer |
| 上传/新建/删除/下载 | 各按钮 | 标准 FileSection CRUD 操作 |
| 拖出到 prompt | 任意文件 | 拖拽 `[file: path]` 到 textarea |
| 自动刷新 | 定时器 | 10s 轮询（page visible） |

> 右侧面板宽 300px，收起时 24px。仅在 `activeProjectId` 存在时显示 FileSection，否则显示 "No active project"。

### 3.10 FileViewer（文件查看器 — notebook-area 内互斥）

| 操作 | 组件 | 流程 |
|------|------|------|
| 打开 | `setOpenFile(file)` | → `useFileStream()` → WS `file-open`；中心区显示 FileViewer |
| 关闭 | StatusBar ✕ 或文件标签 × | `setOpenFile(null)` → 中心区恢复之前视图 |
| 最大化 | StatusBar ⛶ | `toggleFileViewerMaximized()` → `.app-body--fv-maximized` 隐藏左右侧栏 |
| Edit/Preview 切换 | StatusBar | `setMode('edit'/'render')` (仅 text/html 可编辑) |
| 保存编辑 | FileViewerEditor | WS `file-save` → 等待 `file-save-ok` |
| 文本选中批注 | FileViewerRender | mouseUp → FileSelectionFloat → Delete/Replace/Comment/Insert |
| 发送批注到 prompt | 批注卡片 Send | `onSendToPrompt()` → `submitPrompt()` → `nb:appendPrompt` event |
| 批注持久化 | useAnnotationPersistence | L1: localStorage 50ms / L2: WS `annotation-sync` adaptive |

**支持格式**: text / markdown / html / PDF
**不支持**: pptx / docx / xlsx → 服务端返回 `unsupported` → 显示错误文字

> FileViewer 位于 `notebook-area` **内部**，与 Notebook/Git/Welcome 等视图互斥渲染。
> 打开/关闭 FileViewer 时自动保存和恢复 `app-content` 的滚动位置。
> 最大化通过 `.app-body--fv-maximized` class 实现（`display:none` 隐藏 `.sidebar` 和 `.right-panel`）。

### 3.11 WebSocket 生命周期

| 阶段 | 流程 |
|------|------|
| 连接 | `useWebSocket` mount → `connectWebSocket()` → WSS + token |
| 重连 | 3s 定时检查 → 最多 10 次 → 耗尽显示 banner |
| 心跳 | 每 10s ping → 4s 内无 pong → close |
| 会话切换 | sessionId 变化 → unsubscribe 旧 → subscribe 新 |
| 消息分发 | wsSlice onmessage → switch(type) → 调用 store actions |

## 六、后端 API 端点汇总

### 项目文件 CRUD (`/api/projects/{projectId}`)

| 方法 | 路径 | 功能 |
|------|------|------|
| GET | `/files?path=` | 列出目录内容 |
| POST | `/files?path=` | 上传文件（multer multipart） |
| POST | `/files/new-file?path=&name=` | 新建空文件 |
| POST | `/files/mkdir?path=&name=` | 新建文件夹 |
| DELETE | `/files?path=` | 删除文件/文件夹 |
| GET | `/files/download?path=` | 下载单个文件 |
| GET | `/files/zip` | 下载全部为 tar.gz |

### 安全措施
- 所有路径操作经 `validateWorkspacePath()` 防路径穿越（含 symlink 解析）
- dotfile 白名单精确匹配，默认隐藏点文件
- 上传限制：100MB/文件，20 文件/次
- 认证 middleware 全局挂载（`NB_AUTH_TOKEN` 环境变量启用时）

## 七、已知问题

### 问题 #1: pptx/docx/xlsx 不支持预览

**现状**: 服务端对 Office 文件返回 `unsupported` format，前端显示 "This file format is not supported for preview."
**严重度**: 中

> 后端已有 LibreOffice headless 转换逻辑（ws-handler.ts `file-open` 中），但需安装 LibreOffice。

### 问题 #2: 两处 Notebook 创建入口逻辑重复

**现状**: `WelcomeScreen` 和 `NotebookCreationPanel` 各有独立的创建/导入流程，逻辑几乎完全相同。
**严重度**: 低

> 可提取为共享组件或 hook。
