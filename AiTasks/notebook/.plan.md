# Implementation Plan: Claude Code Notebook

## 概述

构建一个类似 JupyterLab 的 Notebook 系统，以 Claude Agent SDK 为"内核"，将交互过程固化为可共享、可重放的 HTML 文件。

## Step 2: 共享数据模型 (packages/shared)

**目标**: 定义 Notebook 文件格式和 WebSocket 消息协议的 TypeScript 类型

核心类型:
- `Notebook` — 顶层文档结构
- `Cell` — prompt cell 或 markdown cell
- `CellOutput` — assistant_message / tool_use / tool_result / error
- `WSMessage` — WebSocket 消息协议 (execute_request, cell_output, execution_complete 等)
- `ExportOptions` — HTML 导出配置

## Step 3: 后端 Agent 服务 (packages/server)

**目标**: 用 Claude Agent SDK 实现 notebook "内核"

核心功能:
1. **SessionManager**: 管理多个 notebook 会话，每个会话维护一个 Agent SDK query 实例
2. **WebSocket 服务**: 接收 `execute_request`，调用 `query()`，流式转发 `SDKMessage` 给前端
3. **Notebook 持久化**: 读写 `.notebook.json` 文件
4. **HTML 导出**: 将 notebook 渲染为自包含 HTML

关键实现:
```typescript
// agent.ts — 核心执行逻辑
import { query } from "@anthropic-ai/claude-agent-sdk";

async function* executeCell(prompt: string, options: NotebookMetadata) {
  for await (const message of query({
    prompt,
    options: {
      allowedTools: options.allowed_tools,
      permissionMode: "bypassPermissions",
      cwd: options.cwd,
      model: options.model,
      includePartialMessages: true,
      systemPrompt: options.system_prompt || undefined,
    }
  })) {
    yield message; // 流式转发给前端
  }
}
```

## Step 4: 前端 Notebook UI (packages/web)

**目标**: React 实现 notebook 界面

核心组件:
1. **Notebook**: 顶层容器，管理 cells 数组
2. **Cell**: 单个 cell，包含输入区和输出区
3. **CellInput**: prompt 编辑器（文本区域 + 运行按钮）或 markdown 编辑器
4. **CellOutput**: 渲染 Claude 的响应（文本、工具调用、工具结果）
5. **Toolbar**: 文件操作（新建、打开、保存、导出 HTML）

关键交互:
- 用户在 CellInput 中输入 prompt，按 Shift+Enter 执行
- WebSocket 实时接收 Agent SDK 的流式消息
- 输出逐步渲染：思考文本、工具调用高亮、工具结果折叠
- 支持添加/删除/移动 cell

## Step 5: HTML 导出引擎

**目标**: 将 notebook 导出为自包含 HTML 文件

HTML 文件结构:
```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>Notebook Title</title>
  <style>/* 内联所有 CSS */</style>
</head>
<body>
  <div id="notebook-root">
    <!-- 静态渲染的 cells -->
    <div class="cell" data-cell-id="xxx">
      <div class="cell-input">...</div>
      <div class="cell-output">...</div>
    </div>
  </div>

  <script id="notebook-data" type="application/json">
    // 完整的 notebook JSON 嵌入
  </script>

  <script>
    // 重放引擎：连接到服务器重新执行
    // 读取 notebook-data，逐 cell 发送 execute_request
  </script>
</body>
</html>
```

**两种模式**:
1. **静态查看**: 直接用浏览器打开，看到固化的输入/输出
2. **重放执行**: 连接到运行 notebook-ai server 的机器，重新执行所有 cell

## Step 6: 重放引擎

**目标**: 支持在另一台机器上重新执行 notebook

实现方式:
1. HTML 文件中嵌入完整的 notebook JSON (prompts + metadata)
2. HTML 文件中包含一个轻量的重放 UI + WebSocket 客户端
3. 用户在另一台机器上:
   - 启动 `notebook-ai server`
   - 用浏览器打开共享的 HTML 文件
   - 点击"重放"按钮，连接到本地 server
   - 逐 cell 重新执行，用新输出替换旧输出

```typescript
// 重放流程
async function replay(notebook: Notebook, serverUrl: string) {
  const ws = new WebSocket(serverUrl);
  for (const cell of notebook.cells) {
    if (cell.type === "prompt") {
      ws.send(JSON.stringify({
        type: "execute_request",
        cell_id: cell.id,
        source: cell.source
      }));
      // 等待 execution_complete
    }
  }
}
```

## Step 7: 集成测试 & 文档

**目标**: 确保端到端工作流正确

测试场景:
1. 创建 notebook -> 添加 cell -> 执行 -> 查看输出
2. 保存 notebook -> 重新打开 -> 内容完整
3. 导出 HTML -> 浏览器打开 -> 静态查看正确
4. 导出 HTML -> 另一台机器重放 -> 新输出正确生成

## 技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 包管理器 | pnpm | 高效的 monorepo 支持 |
| 前端框架 | React + TypeScript | 生态成熟、组件模型适合 cell UI |
| 后端框架 | Express + ws | 简单可靠、WebSocket 原生支持 |
| 构建工具 | Vite (前端) + tsx (后端) | 快速开发体验 |
| Notebook 格式 | JSON (.notebook.json) | 类似 .ipynb，易于序列化、diffable |
| HTML 导出 | 自定义模板引擎 | 需要嵌入重放逻辑，nbconvert 不适用 |

## 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| API key 安全 | key 仅在 server 端使用，HTML 导出中不包含 |
| 大输出性能 | 流式渲染 + 虚拟滚动 + 输出截断 |
| WebSocket 断连 | 自动重连 + 请求队列 |
| 重放一致性 | 重放使用相同 model/prompt/tools，但输出不保证完全一致（LLM 特性）|
| 文件系统访问 | server 端的 cwd 配置，重放时需要相同的项目目录结构 |
