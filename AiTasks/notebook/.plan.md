# Implementation Plan: Claude Code Notebook

## 概述

构建一个类似 JupyterLab 的 Notebook 系统，以 Claude Agent SDK 为"内核"，将交互过程固化为可共享、可重放的 HTML 文件。

> 💬 **关于 "Claude Agent SDK"**: 使用 SDK 是否还可以以订阅模式使用账户？
>
> **调查结论**: Agent SDK 目前**仅支持 API key 认证**，不支持 Pro/Max 订阅计费。Anthropic 明确禁止第三方开发者在 SDK 构建的产品中使用 claude.ai 登录或订阅额度。社区有非官方的变通方案（如 `claude_max`、`ai-sdk-provider-claude-code`），但不是官方支持的方式。因此本项目需要用户提供 `ANTHROPIC_API_KEY`。
>
> 参考: [Issue #559](https://github.com/anthropics/claude-agent-sdk-python/issues/559), [Issue #11](https://github.com/anthropics/claude-agent-sdk-typescript/issues/11)

> 💬 **替代方案：直接使用 Claude Code CLI**: 既然 Agent SDK 仅支持 API key，那直接使用 claude code 是否可以？在 tmux 之中启动 claude code 进程，将前端用户输入转发到 claude 输入命令行，将 claude 输出以 SSE/WebSocket 形式输出到前端 notebook，包括思考过程。
>
> **可行性分析**:
>
> **优势**:
> - 可使用 Pro/Max 订阅，无需 API key 和按量计费
> - `claude -p` headless 模式 + `--output-format stream-json` 提供结构化流式输出
> - `--verbose` + `--include-partial-messages` 可输出 token 级别事件（含思考过程）
> - `--continue` / `--resume <session_id>` 支持多轮对话
> - Claude Code 自带完整工具链（Read、Edit、Bash、Glob、Grep 等）
>
> **实现方式**:
> - 服务端通过 `child_process.spawn` 启动 `claude -p --output-format stream-json --verbose` 子进程
> - stdin 写入用户 prompt，stdout 逐行解析 JSON 事件流
> - 将解析后的事件通过 WebSocket/SSE 转发给前端
> - 无需 tmux —— Node.js `child_process` 已足够管理子进程生命周期
>
> **风险**:
> - 已知问题：stdin 输入超过约 7000 字符时可能产生空输出（需分片或写入临时文件）
> - Claude Code CLI 是面向开发者的工具，不是正式的 API 集成方式
> - 进程管理复杂度高于 SDK 的函数调用
> - 版本更新可能改变 CLI 输出格式
>
> **结论**: 技术上可行，且能显著降低使用成本（订阅制 vs 按量计费）。建议将架构调整为 **Claude Code CLI 子进程方案**，放弃 Agent SDK。核心变更：`agent.ts` 中用 `child_process.spawn('claude', ['-p', '--output-format', 'stream-json', '--verbose'])` 替代 `query()`。

> 💬 **关于 Node.js `child_process` 多轮对话**: 子进程方案是不是执行完一个 prompt 就退出了？下次输入需要再次启动新进程，重新加载上下文？
>
> **调查结论**: 是的，`claude -p` 是单次执行模式 —— 处理完一个 prompt 后进程即退出。多轮对话的实现方式如下：
>
> **会话恢复机制**:
> - 每次 `claude -p` 执行后，完整对话记录保存到 `~/.claude/projects/[编码路径]/[SESSION_UUID].jsonl`
> - 下次执行时使用 `--continue`（恢复最近会话）或 `--resume <session_id>`（恢复指定会话）
> - 恢复时，CLI 读取整个 JSONL 文件，将完整历史作为上下文发送给 API
> - 可通过 `--output-format json` 的返回值中提取 `session_id`，用于后续精确恢复
>
> **性能开销**:
> - 每次进程启动约 **~12 秒**冷启动开销（Node.js 初始化 + 系统 prompt 加载 + MCP 服务器启动 + JSONL 重放）
> - 全量历史 token 重发：第 N 轮会话需重发前 N-1 轮的所有内容（prompt caching 可缓解，5-60 分钟 TTL）
> - Agent SDK 的 warm session 仅需 ~2-3 秒/轮
>
> **对 Notebook 架构的影响**:
> - 每个 Cell 执行 = 一次 `claude -p` 进程启动 + 退出（~12 秒额外延迟）
> - Cell 间上下文连续性依赖 `--resume <session_id>` 机制
> - 长 notebook（多 cell）的上下文重传成本递增
> - 替代方案：`tmux send-keys` 可向交互模式的 Claude Code 发送输入（社区验证可行），但稳定性不如 `-p` 模式
>
> **建议**: Notebook 中每个 cell 应记录 `session_id`，后续 cell 执行时使用 `--resume <session_id>` 保持对话上下文。接受 ~12 秒/cell 的启动开销作为 trade-off（换取订阅制零 API 成本）。

## Step 2: 共享数据模型 (packages/shared)

**目标**: 定义 Notebook 文件格式和 WebSocket 消息协议的 TypeScript 类型

核心类型:
- `Notebook` — 顶层文档结构
- `Cell` — prompt cell 或 markdown cell
- `CellOutput` — assistant_message / tool_use / tool_result / error
- `WSMessage` — WebSocket 消息协议 (execute_request, cell_output, execution_complete 等)
- `ExportOptions` — HTML 导出配置

## Step 3: 后端 Agent 服务 (packages/server)

**目标**: 用 Claude Agent SDK 实现 notebook "内核"

核心功能:
1. **SessionManager**: 管理多个 notebook 会话，每个会话维护一个 Agent SDK query 实例
2. **WebSocket 服务**: 接收 `execute_request`，调用 `query()`，流式转发 `SDKMessage` 给前端
3. **Notebook 持久化**: 读写 `.notebook.json` 文件
4. **HTML 导出**: 将 notebook 渲染为自包含 HTML

关键实现:
```typescript
// agent.ts — 核心执行逻辑
import { query } from "@anthropic-ai/claude-agent-sdk";

async function* executeCell(prompt: string, options: NotebookMetadata) {
  for await (const message of query({
    prompt,
    options: {
      allowedTools: options.allowed_tools,
      permissionMode: "bypassPermissions",
      cwd: options.cwd,
      model: options.model,
      includePartialMessages: true,
      systemPrompt: options.system_prompt || undefined,
    }
  })) {
    yield message; // 流式转发给前端
  }
}
```

## Step 4: 前端 Notebook UI (packages/web)

**目标**: React 实现 notebook 界面

核心组件:
1. **Notebook**: 顶层容器，管理 cells 数组
2. **Cell**: 单个 cell，包含输入区和输出区
3. **CellInput**: prompt 编辑器（文本区域 + 运行按钮）或 markdown 编辑器
4. **CellOutput**: 渲染 Claude 的响应（文本、工具调用、工具结果）
5. **Toolbar**: 文件操作（新建、打开、保存、导出 HTML）

关键交互:
- 用户在 CellInput 中输入 prompt，按 Shift+Enter 执行
- WebSocket 实时接收 Agent SDK 的流式消息
- 输出逐步渲染：思考文本、工具调用高亮、工具结果折叠
- 支持添加/删除/移动 cell

**两种模式**:
1. **静态查看**: 直接用浏览器打开，看到固化的输入/输出
2. **重放执行**: 连接到运行 notebook-ai server 的机器，重新执行所有 cell

## Step 6: 重放引擎

**目标**: 支持在另一台机器上重新执行 notebook

实现方式:
1. HTML 文件中嵌入完整的 notebook JSON (prompts + metadata)
2. HTML 文件中包含一个轻量的重放 UI + WebSocket 客户端
3. 用户在另一台机器上:
   - 启动 `notebook-ai server`
   - 用浏览器打开共享的 HTML 文件
   - 点击"重放"按钮，连接到本地 server
   - 逐 cell 重新执行，用新输出替换旧输出

```typescript
// 重放流程
async function replay(notebook: Notebook, serverUrl: string) {
  const ws = new WebSocket(serverUrl);
  for (const cell of notebook.cells) {
    if (cell.type === "prompt") {
      ws.send(JSON.stringify({
        type: "execute_request",
        cell_id: cell.id,
        source: cell.source
      }));
      // 等待 execution_complete
    }
  }
}
```

## Step 7: 集成测试 & 文档

**目标**: 确保端到端工作流正确

测试场景:
1. 创建 notebook -> 添加 cell -> 执行 -> 查看输出
2. 保存 notebook -> 重新打开 -> 内容完整

## 技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 包管理器 | pnpm | 高效的 monorepo 支持 |
| 前端框架 | React + TypeScript | 生态成熟、组件模型适合 cell UI |
| 后端框架 | Express + ws | 简单可靠、WebSocket 原生支持 |
| 构建工具 | Vite (前端) + tsx (后端) | 快速开发体验 |
| Notebook 格式 | JSON (.notebook.json) | 类似 .ipynb，易于序列化、diffable |
| HTML 导出 | 自定义模板引擎 | 需要嵌入重放逻辑，nbconvert 不适用 |

## 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| API key 安全 | key 仅在 server 端使用，HTML 导出中不包含 |
| 大输出性能 | 流式渲染 + 虚拟滚动 + 输出截断 |
| WebSocket 断连 | 自动重连 + 请求队列 |
| 重放一致性 | 重放使用相同 model/prompt/tools，但输出不保证完全一致（LLM 特性）|
| 文件系统访问 | server 端的 cwd 配置，重放时需要相同的项目目录结构 |
