# Summary: notebook

## Objective

构建一个类似 JupyterLab 的 Notebook 系统，将 Claude Code 置于服务端作为"内核"，将交互过程固化为可共享、可重放的 HTML 文件。

## Architecture

- **前端**: React + TypeScript notebook UI，cell-based 界面
- **后端**: Node.js + tmux 管理 Claude Code 交互会话，JSONL 文件监控获取输出，WebSocket 转发给前端
- **文件格式**: `.notebook.json`（JSON，类似 .ipynb）
- **HTML 导出**: 自包含 HTML，内嵌 notebook 数据 + 重放引擎

## Plan Overview (7 Steps)

1. 项目脚手架 (pnpm monorepo)
2. 共享数据模型 (TypeScript types)
3. 后端 Agent 服务 (Claude Code CLI + WebSocket)
4. 前端 Notebook UI (React cells)
5. HTML 导出引擎 (自包含)
6. 重放引擎 (跨机器执行)
7. 集成测试 & 文档

## Key Decisions

- **推荐架构**: tmux + Claude Code 交互模式（方案 B）— 常驻进程，零 cell 间启动开销
- 输入: `tmux send-keys` 注入 prompt（PTY 层级，社区验证有效）
- 输出: 监控 JSONL 会话文件 + `Stop` hook 完成信号（不解析终端输出）
- JSON 格式存储，HTML 为导出衍生物
- 重放需要目标机器运行 server + Claude Code
- **认证**: 可使用 Pro/Max 订阅（零 API 成本）

## Architecture Evolution (注释链)

1. 初始方案: Agent SDK `query()` → 仅支持 API key，放弃
2. 方案 A: `claude -p` 子进程 → 每 cell ~12 秒冷启动 + token 重传
3. **方案 B (推荐)**: tmux + 交互模式 → 常驻进程，JSONL 监控，社区验证（ccbot、claudecode-telegram）
4. 备选 C: `claude -p --input-format stream-json` 常驻管道 → 干净 JSON 但有已知 bug
